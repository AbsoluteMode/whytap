# Wake word

## Context

Drop needs a held or tapped key. The user wants hands-free dictation: say a
phrase, speak, and have the text pasted when they stop. ElevenLabs
`scribe_v3_live` (the user's Drop route since 2026-11-11) can predict the end of
a turn, which removes the need for a key at the end as well.

## Decision

- **Opt-in, off by default** (Settings -> Other -> Wake word). An always-on
  microphone is never a default, and macOS shows its indicator while it listens.
- **On-device spotter.** sherpa-onnx v2.0.1 keyword spotting with the bundled
  `sherpa-onnx-kws-zipformer-gigaspeech-3.3M-2024-01-01` int8 model (5.5 MB,
  Apache-2.0, English, open vocabulary). The user explicitly approved this
  second on-device model; Invariant 3 names it next to Silero VAD. It decides
  only "was the phrase said"; speech recognition still runs on the user's
  chosen provider.
- **Nothing leaves the Mac before dictation starts.** Listener audio goes from
  the microphone into the spotter and is dropped: no file, no log, no network.
  Logs record that the phrase was heard, never which phrase or any audio.
- **Phrases are text, not training.** The user types phrases; `WakeWordTokenizer`
  encodes them in Swift (SentencePiece unigram Viterbi over the model's
  `bpe.model`). The model is English, so a phrase is written the way an English
  listener hears it. Default `why tap, why tab`; the user adds what the model
  hears in their own voice.
- **A wake word starts an ordinary Drop take** through the same dispatcher as
  the hotkey (mode latch, permissions, paste target, island UI), and only with
  positive evidence of a focused editable field
  (`PasteTargetValidator.appHasFocusedTextInput(requiringEvidence: true)`): a
  text role or subrole whose value or selected text is settable, or any
  element with settable selected text. Read-only text (it keeps the text
  role), a slider or scroll bar with a settable value, unknown or unavailable
  focus and a bare web area are a no, so an accidental phrase
  cannot stream the room to a provider with nowhere to paste. The permissive
  rules stay for the history paste hint and hold-Space, where a key was
  pressed. An app that exposes no accessibility focus cannot be dictated into
  by wake word; its hotkey still works.
- **The builder's meeting gate is unchanged.** It reads any microphone use as
  a possible call, and the idle listener would hold it busy forever. App
  control gains `wakeWordPaused`: memory-only, it releases the listener for up
  to three minutes and ends by itself. The builder sets it, then runs the gate
  against the real microphone state (shared-app process, step 5).
- **The take ends by itself.** `WakeTakeEndpointer` finishes it 2 s after the
  live transcript stops changing, cancels it, pasting nothing, if no words
  arrive within 5 s of recording (under the session's 6 s silent-stall check),
  and ends any take at 60 s so a false trigger near a TV cannot stream the
  room for the hotkey's 10-minute cap. A self-hosted server route transcribes
  only after a commit, so a wake word starts nothing there. If the connection
  fails and the batch recorder takes over, the recording is transcribed at
  the timeout instead of discarded. On ElevenLabs `scribe_v3_live` the take also asks for
  `commit_strategy=turn_prediction`; the provider's first commit with words is
  the terminal and resolves `.endpointDetected`, a legitimate finish; a
  closed socket in that mode is a transport error, so the retained audio is
  recovered. Other models and providers keep manual commit and rely on the
  endpointer.
- **The microphone is open only when a take could start:** enabled, awake,
  Drop and Agent idle, no meeting recording, no screenshot.
- **Never a wireless microphone.** Holding a Bluetooth one open keeps
  headphones in the call profile. The listener uses the default input only
  when it is built in or USB; otherwise the built-in microphone, and stays off
  on a Mac without one.

- **Timings are calibrated on real speech, without rebuilds.** `WakeWordTuning`
  reads two optional defaults when a take starts: `com.sidekey.wakeword.quietSeconds`
  (0.5-5, default 2) and `com.sidekey.wakeword.providerSilenceSeconds` (0.3-3,
  default 1.5, sent as `vad_silence_threshold_secs`). They have no UI until the
  values settle.

## Why

- A dedicated spotter costs under 1% of one core (measured real-time factor
  0.009 on Apple Silicon); streaming to a provider around the clock would cost
  about $5 a day and send room audio off the Mac.
- sherpa-onnx is the only surveyed engine with training-free custom phrases,
  no account, an Apache-2.0 model and prebuilt universal macOS libraries.
- Reusing the Drop dispatcher keeps every Drop contract (strict modes, Retry,
  resilient delivery) instead of a parallel dictation path.

## What was tested

- Prototype on the user's voice: the model never heard "why tap"; it heard
  "wait up" (6), "right up" (5), "white up", "wide up". With those phrases it
  fired 8 times. Hence editable phrases rather than a fixed word.
- Synthetic voices at threshold 0.25 missed a lone phrase that 0.10 caught;
  0.10 is the shipped threshold.
- Token order by id and greedy BPE merges both disagreed with SentencePiece
  (13,365 and 20,024 of 20,000-30,000 phrases); unigram Viterbi matched 50,000
  of 50,000.
- The static xcframeworks contain arm64 and x86_64; a probe binary linked and
  detected the same phrases as the Python build.

## Not verified

- `turn_prediction` against a live ElevenLabs socket (LIVE-VERIFY in
  `ElevenLabsRealtimeURL`). A rejected parameter degrades to batch recovery.
- Real microphone capture, the Bluetooth fallback and the installed-app flow.
- False-trigger rate in everyday use. Common-word phrases such as "wait up"
  do fire on English speech.
- Whether `scribe_v3_live` still force-commits a segment at about 36 s under
  turn prediction; if it does, a longer hands-free dictation ends there.
- The listener keeps running with the screen locked; only system sleep
  pauses it.

## Review

An independent review of the first implementation found, and this version
fixes: the reader task outliving every stop (leaking the microphone source and
the loaded model), no cap on a falsely triggered take, a socket close reported
as a finished turn, endless retries after a denied microphone, and phrase
validation that accepted letters with combining marks.

The builder then blocked the first submitted head on two points, fixed in the
next one: the focus check accepted unknown focus and a generic web area, and
the idle microphone was incompatible with the automatic restart's meeting gate.
It blocked the second head because the strict check still accepted read-only
text and non-text controls with a settable value; the rule above is the fix.

## Rejected

- Vosk: phrases must be dictionary words; no macOS library since 2022.
- openWakeWord, livekit-wakeword, microWakeWord: a model must be trained per phrase.
- Porcupine: needs an account and access key.
- Apple SpeechAnalyzer: macOS 26 only; energy over hours unmeasured.
- Detecting the phrase in provider transcripts: constant audio upload and cost.
- Downloading the model on first use: the bundled 5.5 MB keeps Invariant 1's
  network list unchanged and works offline.
- The upstream sherpa-onnx Swift package: it would clone the whole repository;
  the app declares the two binary targets and wraps the C API.

## Cost

The static libraries add roughly 23-35 MB per architecture to the executable.
