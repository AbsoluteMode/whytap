# Диагностический трейс дроп-турна: фазовый таймлайн + turn-watchdog

## Контекст

Прод-баг «syncing висит»: после диктовки Dynamic Island застревает на
«thinking…» — иногда падает через ~50с (`voice_turn_failed`), иногда висит до
рестарта; надиктовка теряется. #351 закрыл AX-walk (одну манифестацию, uid=10),
но зависания остались: у seva (uid=15, уже на 1.9.3) и вживую у Максима (его
голосовой ввод отвалился прямо во время сессии).

Провайдерную гипотезу отвергли. Максим — на Soniox и без проблем; падения
интермиттентные на всех провайдерах (включая Максима live на Soniox).
«Корреляция soniox = плохо» оказалась артефактом джойна **текущего**
`transcription_provider` к **историческим** падениям — провайдер пользователи
переключают. Первопричина неизвестна → надо локализовать, ГДЕ турн встаёт.

Ключевое из прод-логов: при бесконечном висяке `await session.run()` не
возвращается → `handleStreamingResult` не зовётся → не эмитится ни
`voice_turn_completed`, ни `voice_turn_failed`. В телеметрии остаётся
осиротевший `voice_turn_started` (ровно случай Максима: 10:35:54 started,
дальше тишина). А пост-stop watchdog сессии (`SonioxStreamingSession`, 10с)
армится только внутри `stop()` — значит висяк ДО stop или при недетекте
release ничем не ограничен и в телеметрии невидим.

## Решение

`DropTurnTrace` — privacy-safe аккумулятор на один турн: фазовый таймлайн
(`started → recording → first_token → stop_requested → resolving → done`) +
счётчик входящих токенов. Эмитит плоский payload (`turn_id`, `last_phase`,
`<phase>_ms` офсеты, `token_count`, `stop_requested`) на терминальном событии.
Текста НЕТ — только счётчики/тайминги/id/bool.

Плюс turn-level watchdog в `AppDelegate` (75с): если турн не достиг терминала,
стреляет `voice_turn_failed outcome=stuck reason=turn_watchdog_<last_phase>` —
закрывает «немой» бесконечный висяк. Диагностика-only: фазу/флоу не трогает
(репро сохраняется для последующего фикса).

Заодно: настоящий `turn_id` (был захардкожен `"pending"` — события турна не
связывались) + `os_log` на границах фаз для живого `log stream`.

## Почему

Телеметрия знала только терминальный `reason`, но не таймлайн, который к нему
привёл. `last_phase` + `stop_requested` разводят локус сбоя:

- `recording` без `first_token` → WS открыт, но ничего не транскрибировалось
  (аудио не течёт / сервер молчит);
- `first_token` без `stop_requested` → release не дошёл до `stop()` — вот он,
  неограниченный висяк, который пост-stop watchdog поймать не может;
- `stop_requested` без `done` → зависла финализация.

75с у turn-watchdog — заведомо больше любого естественного разрешения (макс.
удержание + 10с watchdog сессии), чтобы он стрелял ТОЛЬКО по настоящим висякам
и не перебивал реальный терминальный `reason`.

Privacy: только счётчики/офсеты/id/bool → в отличие от временного
`drop_phase_debug` (#350, светил `String(describing: wing)` = live-транскрипт,
нарушение инварианта #3) может жить в проде постоянно.

## Что протестировали

- **Провайдерная гипотеза** — отвергнута: Максим на Soniox чист; интермиттентно
  на всех провайдерах; джойн current-vs-historical недостоверен.
- **Бэкенд-логи**: зависший турн = `stream_v2.session.started` → тишина (ни
  `/api/process`, ни терминала), при здоровом бэкенде (соседние турны ok).
- **TDD**: 4 теста `DropTurnTrace` — таймлайн+офсеты; stuck-before-stop →
  `recording`/no-stop/no-token; furthest-phase + first-stamp-wins; privacy
  (нет `transcript`/`text`, только `token_count`).
- **Полный сьют**: 2975 тестов, мои зелёные. 7 падений только в
  `Telegram*ListenerTests` («poll timed out») — воспроизводятся и на чистом
  main без правок (предсуществующий флак, не регресс).

## Отвергли

- **Переключить пользователей на ElevenLabs** — провайдер не корень.
- **Watchdog со сбросом фазы в idle (авто-recovery)** — симптом-фикс до
  первопричины (Iron Law), маскирует репро. Recovery — следующим шагом, когда
  `last_phase` покажет, где встаёт.
- **Вернуть `drop_phase_debug` (#350)** — утечка транскрипта.
- **Только `os_log` + ручной сбор логов** — не масштабируется на пользователей
  и не ловит «немой» бесконечный висяк автоматически.
