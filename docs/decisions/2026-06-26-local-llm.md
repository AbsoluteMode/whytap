# ROO-257 — on-device LLM (Drop cleanup + fully-local meeting)

**Дата:** 2026-06-26
**Где:** `Sources/Sidekey/LLM/Local`, `Sources/Sidekey/LLM/Diarization`,
`Sources/Sidekey/Meetings/MeetingLocal*`, `MeetingsCoordinator`,
`SettingsModelsView*`, `scripts/build-metallib.sh`.

## Контекст

ROO-257 расширяет local-стек ROO-256 (local STT) до полноценного on-device
LLM: PRO-юзер выбирает LLM-уровень **Local**, один раз качает модель — дальше
(1) smart-cleanup диктовки (Drop) и (2) митинги работают локально, офлайн, без
сервера и без расхода минут. Митинги — полностью на устройстве, с локальной
диаризацией: микрофон = «Я», системный звук диаризуется на удалённых спикеров.

## Решения

### Движок: MLX + Qwen3-4B-Instruct-2507-4bit

- `ml-explore/mlx-swift` + `ml-explore/mlx-swift-lm` (MLXLLM/MLXLMCommon).
  MLX — нативный Apple-Silicon ML-фреймворк (Metal + ANE), оптимальный для
  on-device инференса на маках.
- Модель `mlx-community/Qwen3-4B-Instruct-2507-4bit`: 4B параметров, 4-bit
  квантизация — баланс качества cleanup/summary и памяти (помещается рядом с
  STT/диаризатором на 8 GB маках при сериализации, см. eviction ниже).
- `LocalLLMModelStore` — зеркало `LocalTranscriptionModelStore`: download HF
  Hub → app-owned cache `Application Support/Sidekey/LocalLLMModels/...`,
  статус/прогресс/delete, лениво кэшируемый `ModelContainer`.

### Диаризация: FluidAudio on-device, mic=«Me» + диаризованный system-track

- Диаризация удалённых спикеров — FluidAudio Core ML (`DiarizerManager`,
  уже-подключённая зависимость, без нового supply-chain surface).
- **Отвергли моно-микс.** Митинг-рекордер для local-пути держит mic и system
  как РАЗДЕЛЬНЫЕ 16 кГц дорожки. mic-дорожка тривиально размечается как «Me»;
  только system-дорожка диаризуется → «Speaker N». Диаризация моно-микса (mic+
  system вместе) спутала бы голос юзера с удалёнными и дала бы худшее качество.
  Пре-микс остаётся ТОЛЬКО для серверного/BYOK-аплоада (не трогаем).
- Alignment: mic-сегменты + system ASR-сегменты + диаризация-тёрны сливаются по
  времени в единый `[TranscriptSegment]` со `speaker`.

### No usage metering для local-путей

- Local cleanup минует `/api/process`; fully-local meeting минует
  `MeetingsBackendClient` (upload/finalize). Минуты/секунды usage не
  инкрементятся — это и есть продуктовый смысл local-уровня (нулевая серверная
  стоимость, приватность). Инвариант #2 в репо обновлён соответственно.

### Committed metallib artifact (vs build-time)

- SwiftPM (`swift build`, на котором стоят dev-run.sh и build-dmg.sh) **не умеет
  компилировать Metal-шейдеры** — это документировано в upstream mlx-swift.
  Без `default.metallib` первая GPU-операция падает «Failed to load the default
  metallib».
- **Решение:** компилируем metallib один раз через `xcodebuild` против
  резолвнутого mlx-swift checkout (`scripts/build-metallib.sh`) и коммитим как
  `Resources/mlx.metallib` (build-артефакт, как AppIcon.icns). dev-run.sh и
  build-dmg.sh копируют его рядом с executable (Contents/MacOS/mlx.metallib).
- **Version lock:** metallib version-locked к mlx-swift ревизии в
  Package.resolved — бамп MLX требует пересборки metallib (atomic-изменение).
  Зафиксировано в шапке `build-metallib.sh`.
- **Отвергли build-time компиляцию** (перегон каждого билда через xcodebuild):
  ломает быстрый `swift build` dev-loop и требует Metal toolchain на каждом
  билд-агенте. Committed-артефакт — детерминированно и дёшево.

### Apple-Silicon гейт (Stage 6)

- MLX и FluidAudio Core ML — Apple-Silicon-only. Бинарь **universal**, поэтому
  compile-time `#if arch(arm64)` НЕВЕРЕН (Intel-slice / Rosetta мис-репортят).
- **Решение:** runtime-проба `LocalModelSupport.isAppleSilicon` через
  `sysctlbyname("hw.optional.arm64")` — отражает реальный CPU независимо от
  slice. Fail-closed: любая ошибка → «не Apple Silicon» (стек скрыт, а не
  предложен на железе, где не запустится).
- Применён к: `SettingsModelsViewModel.canUseLocal`/`canUseLocalLLM` (Local
  скрыт/дизейблен на Intel с подсказкой «Local models require Apple Silicon»),
  и `MeetingsCoordinator.isFullyLocalMeetingEnabled` (на Intel всегда false —
  local-митинг не активируется). Local STT (ROO-256) гейта НЕ имел — ROO-257
  добавил единый источник истины для обоих.

### Eviction / сериализация моделей (память)

- Три on-device модели (Parakeet STT, диаризатор, LLM) на 8 GB маке вместе не
  помещаются. `MeetingLocalProcessor` грузит их СЕРИАЛЬНО, вызывая `evict()` на
  каждом сторе между стадиями (transcribe → diarize → summarize). `evict()`
  сбрасывает кэшированный manager/container; веса остаются на диске, следующий
  load перечитывает с диска. WHY-якорь — в `MeetingLocalProcessor` и
  `LocalLLMModelStore.evict()`.

### Производительность local Drop (perf-pass, 2026-06-27)

Первый рабочий local-stack (ROO-256 STT + ROO-257 LLM) сильно лагал на Apple
Silicon при Smart Drop + Local STT/LLM. Корневые причины и фиксы:

- **Partial decode был O(buffer).** `LocalTranscriptionSession` пере-декодировал
  ВЕСЬ накопленный буфер каждые ~400 мс со СВЕЖИМ `TdtDecoderState`. Под 15 c
  это фиксированный, но тяжёлый прогон энкодера по padded-окну 240k семплов на
  тик; за 15 c — переход в `ChunkProcessor` и истинный линейный рост. Декоды
  отставали от речи на ~6 c и пинали ядро. **Фикс:** инкрементальные партиалы —
  `ParakeetLocalASRDecoder` стал `actor`, несёт `TdtDecoderState` вперёд и
  декодирует ТОЛЬКО новый срез аудио за тик (`decodePartial`, O(chunk)). Финал
  на stop остался свежим полно-буферным `decode` (авторитетный, paste без
  изменений). `LocalStreamingASRDecoding` — расширение seam'а.
- **Decode держал main actor / QoS event-tap'а.** Drain-loop переведён на
  `Task(priority: .utility)`; тяжёлая работа уходит на actor декодера, на main
  остаётся только cheap guard + island-callback. Hover CGEventTap не голодает.
- **LLM оставался резидентным.** `evict()` был только в `MeetingLocalProcessor`,
  не на Drop. `PostProcessor` теперь эвиктит local LLM (`evictLocalLLM` hook)
  после КАЖДОГО `.local` cleanup-тёрна — Drop'ы редкие, держать ~3-4 GB между
  ними = co-residency со STT = системный лаг. Trade-off: следующий local Drop
  перечитывает веса с диска (несколько секунд) — приемлемо для интермиттентного
  cleanup.
- **Smart Drop + Local STT не запускал cleanup (routing-баг).** `AppDelegate`
  безусловно ставил `bypassesPostProcessing` для `LocalTranscriptionSession` —
  это ROO-256 артефакт ДО появления local LLM (тогда отвергли только
  `/api/process`, который ломает offline). Local LLM работает полностью offline,
  поэтому **отменяем blanket-bypass**: `localTranscriptionBypassesPostProcessing`
  решает по режиму+маршруту — Smart + offline-capable route (`.local` /
  `.direct` BYOK) → запускаем on-device cleanup; Fast или backend-only route →
  raw paste (offline сохранён, `/api/process` НЕ дёргаем). Это и есть
  задекларированная цель local LLM («smart-cleanup диктовки (Drop)» выше).
- **Пустой ответ Qwen молча съедал paste (ROO-257).** Деградировавший on-device
  reply бывает whitespace-only; `LocalLLMSession.complete()` тримит его в "",
  и `runPostProcessAndPaste` отдавал "" дальше в paste-хвост, где
  `deliverDropTranscript` имеет `guard !text.isEmpty` → paste молча не
  происходил, ошибка не всплывала (успешный пустой return — не throw, fallback
  на rawText в `catch` не срабатывал). **Фикс:** `dropDeliverableAfterCleanup`
  (pure) — если cleanup пустой/whitespace, отдаём raw-транскрипт (зеркало
  существующего error-fallback). Defense-in-depth: тот же guard после
  `DropFillerFilter.apply` в `finishDropDelivery` — фильтр сам может стереть
  текст в "". Гарантия: при непустой диктовке paste никогда не теряется молча.
  Раньше empty-output путь был полностью не покрыт тестами (моки давали только
  непустой reply) — добавлены кейсы в `AppDelegateDropFlowRouteTests`.

### Унифицированный offline / not-downloaded messaging (Stage 6)

- `LocalModelMessaging` — единые строки для Settings / drop / meetings:
  - `requiresAppleSilicon` — «Local models require Apple Silicon.»
  - `offlineCannotDownload` — «You're offline — connect to the internet to
    download the model.» (офлайн при попытке скачать веса; после скачивания
    inference работает офлайн — в этом и смысл).
  - `modelNotDownloaded` — «Download the local model first.»
- Офлайн-ошибка скачивания детектится по `URLError` (включая обёрнутую в
  `NSUnderlyingErrorKey` HF-ошибку) и маппится на `offlineCannotDownload`.
