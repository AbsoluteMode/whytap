# Onboarding Connect подключает по probe, а не по чеклисту

## Контекст

Репорт тестера на 1.18.9: Codex CLI установлен, авторизован, из терминала
работает — но Whytap его не запускал и «продолжал проверять Claude». Помог
только сброс состояния Agent/onboarding и повторный выбор Codex.

Активный агент живёт в одном ключе — `agent.activeProvider` (UserDefaults),
из него `AppDelegate.startAgentIfEnabled` резолвит, какой CLI спавнить.
Писали его два места, и они работали по разным правилам:

- **Settings → Agents:** `Connect` гоняет `probe()` выбранного провайдера и на
  `.connected` пишет `markConnected(id)`. Контракт прямо записан в коде:
  probe — источник истины, чеклист только подсказка.
- **Онбординг:** активный провайдер писался НЕЯВНО, из `apply()` — как только
  чеклист текущего провайдера становился 4/4 зелёными. Кнопка `Connect` при
  этом не писала провайдера вообще: она поднимала локальный `connectPressed`
  и включала capability Agent.

Отсюда три дефекта, складывающиеся ровно в репорт:

1. **Claude «подключался» сам.** Чузер по умолчанию встаёт на Claude
   (`activeProvider == .codex ? .codex : .claude` — `nil` тоже даёт claude).
   У кого установлен Claude Code и выполнен вход — `markConnected(.claude)`
   уезжал в дефолты через ~2 секунды после простого открытия вкладки Agent,
   без единого клика.
2. **Codex было нечем перебить.** Единственный путь записи `.codex` — тот же
   авто-mark, а он требует все 4 галочки, включая **Homebrew** и **Node.js**.
   Codex из `/Applications/Codex.app` (он первый в `CodexBinaryLocator.knownPaths`)
   или машина без Homebrew → 4/4 не будет никогда → выбор Codex не сохранялся
   никогда, при живом и залогиненном CLI.
3. **Выбор не персистился.** `provider` был производной от
   `agent.activeProvider`; `@StateObject` пересоздавался при переоткрытии окна
   → панель откатывалась на Claude и снова опрашивала его.

## Решение

Онбординг выровнен по контракту Settings → Agents:

- `OnboardingAgentSetupSurface.confirmConnection()` — probe выбранного
  провайдера; только на `.connected` пишется `markConnected`. Homebrew/Node
  остаются подсказкой и НЕ гейтят подключение.
- Неявный `markConnected` из `apply()` удалён: `apply()` теперь только зеркалит
  статусы. Приложение не назначает агента без действия юзера.
- `AgentProviderStore.preferredProvider` (`agent.preferredProvider`) — выбор
  чузера, сохраняемый сразу, до успешного probe. Только UI-restore: диспатч
  турна по-прежнему читает исключительно `activeProvider`. Восстановление —
  `activeProvider ?? preferredProvider`, дефолт Claude только для того, кто
  никогда не выбирал. `disconnect()` выбор не стирает.
- «Connected» в панели = `connectPressed && surface.isConnected`, т.е. пилюля
  показывается, только когда выбранный провайдер реально активный агент.
- Отказ probe больше не молчит: подсказка под кнопкой + копирование команды
  того шага, который реально не прошёл (`.notInstalled` → CLI, `.notSignedIn` →
  sign-in). Раньше кнопка вела к «первому незелёному шагу» — то есть отправляла
  ставить Homebrew человеку, у которого всё уже стояло.

## Почему

Один контракт на оба экрана: **подключение решает probe, чеклист только ведёт
за руку.** Чеклист описывает один сценарий установки (Homebrew → Node → npm),
а реальных больше: app-бандл, nvm, asdf, кастомный npm prefix. Гейтить
подключение на нём — значит запрещать подключиться тем, у кого всё работает.

Неявная запись активного провайдера плоха сама по себе: назначение агента —
решение пользователя, а не побочный эффект открытия вкладки. Именно неявность
делала состояние «залипшим»: юзер не совершал действия, значит и не понимал,
что откатывать; UI при этом показывал Claude как норму.

Персист выбора отдельно от подключения нужен, потому что между «выбрал» и
«подключился» есть реальный интервал — юзер уходит в терминал ставить CLI. До
фикса этот интервал стирал выбор.

## Что протестировали

Юнит-тесты (`RealOnboardingAgentSetupSurfaceTests`, фейковые probes — реальный
CLI не нужен):

- чеклист 4/4 **не** подключает ничего (`activeProvider` остаётся nil);
- connect проходит при отсутствующих Homebrew и Node — сценарий репорта;
- connect Codex перебивает залипший `.claude`;
- отказ probe (`notLoggedIn`, `notInstalled`) не пишет провайдера;
- выбор переживает пересоздание surface без подключения;
- `disconnect()` гасит активного агента, но сохраняет выбор.

Плюс source-guard'ы на панель (`OnboardingAgentConnectPaneTests`): Connect идёт
через `confirmConnection()`, `allSatisfied` больше не гейт, `apply()` не
содержит `markConnected`.

Полный прогон: 3961 тест, 0 падений.

## Отвергли

- **Только убрать авто-mark** — Codex из онбординга по-прежнему не подключить.
- **Только персистить выбор** — панель перестаёт откатываться, но активный
  провайдер не меняется; R⌘ всё так же уходит в Claude.
- **Выкинуть Homebrew/Node из чеклиста** — они полезны тому, кто начинает с
  нуля; проблема была не в их наличии, а в том, что они гейтили подключение.
- **Автоматически подключать провайдера, чей чеклист позеленел** (текущее
  поведение, но для обоих сразу) — усугубляет: гонка «кто позеленел первым»
  вместо выбора юзера.
- **Синхронизировать выбор через сервер (UserPreferencesCache)** — локальный
  CLI и так машинно-специфичен; провайдер на другой машине юзера может быть
  другим.
