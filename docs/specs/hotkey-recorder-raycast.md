# Spec: Рекордер хоткеев — Raycast-модель записи

> Итерация поверх пакета Б (`feature/hotkeys-followups`). После B1–B8 рекордер
> работал по модели «один модификатор + клавиша» с очисткой модификатора на
> отпускании (release-clear, добавлено в B1 ради возврата к bare Space). Это
> дало неинтуитивное поведение: завершённый combo (`⌥D`) терял модификатор при
> отпускании клавиши (поле показывало `D`), голые модификаторы мельтешили,
> разные типы клавиш вели себя по-разному. Решение Максима: переписать рекордер
> по образцу Raycast (release-to-commit). Агент, мониторы, конфликт-модель,
> структура данных — не трогаем.
>
> Статус: реализован (R1 7d0956e+1b2bc83, R2 b15d03c, R3 b3db3ab+8889627;
> subagent-driven, spec+quality ревью на каждом таске). Полный suite 2577/0/2skip.
> Ручной чеклист R4 — на Максиме. Дизайн одобрен 13 июня (серия итераций).

## Что строим

Рекордер записи хоткея ведёт себя как в Raycast:

1. Пользователь жмёт «изменить хоткей» → поле записи активируется.
2. Жмёт клавиши — каждая нажатая появляется в поле (модификаторы + символ).
3. **Отпускает комбинацию → она фиксируется** в поле (в draft). Нажал одну
   клавишу и отпустил → зафиксирована одна.
4. **Escape** — выход из записи без фиксации (поле разблокируется, биндинг
   остаётся прежним). Escape сам по себе не записывается.
5. Применение в рантайм — по кнопке **Save** (существующий `apply(draft)`).

## Модель биндинга (финальная)

- **Хоткей = комбинация модификаторов + один символ.**
  - **Модификаторы:** `⌘ ⌥ ⌃ ⇧` (+`Fn` если ловится) — любое подмножество.
    **Сторона (левый/правый) в комбо не важна** — как в Raycast («любой ⌘ + A»).
    Безопасно: комбо требует символ, от одиночного нажатия ⌘ не срабатывает.
  - **Символ:** любая не-модификаторная физическая клавиша (буквы, цифры,
    стрелки, F-клавиши, Tab, Enter, Delete…), по **keyCode**.
- **Голый символ** (без модификаторов) — валиден (Space, стрелки —
  дефолты Useful Links, и т.п.).
- **Голый одиночный модификатор** — только **правые `R⌘ R⌥`** (детекция по
  device-биту, существующий механизм `ModifierOnlyHotkeyMonitor`). Сторона
  важна ТОЛЬКО здесь: голый правый модификатор не конфликтует с левым `⌘C`.
  Это путь агента (`R⌘`, tap/hold) и Drop-на-`R⌥`. Левые одиночными не делаем —
  без стороны «любой ⌘ один» срабатывал бы на каждый `⌘C`.
- **Триггер и хранение — по физической клавише (keyCode), не по символу.**
  Раскладка/язык меняют символ, физическая позиция — нет.

## Режимы (gesture)

- **voice** (Drop voice, Agent voice): **tap / hold** (как B3/B5; `.tap`
  отображается как «Toggle» на voice-строках — B6 `voiceTitle`).
- **остальные** хоткеи: только **tap**.

## Почему

- Модель «один модификатор + clear-on-release» из B1 дала класс багов:
  combo теряет модификатор на отпускании, мельтешение голых модификаторов,
  непредсказуемость. Максим: «вообще непонятно как хоткеи проставляются».
- Raycast-модель (release-to-commit) убирает этот класс **по построению**:
  отпускание — это фиксация, а не очистка. Поведение единообразно для всех
  типов клавиш.

## Scope

### In
- Переписать `HotkeyShortcutRecorder` на **release-to-commit**:
  отслеживать набор одновременно зажатых клавиш; модификаторы аккумулируются
  в маску, последний не-модификатор = символ-слот; по отпусканию ВСЕХ клавиш
  набор фиксируется (в draft через `assignShortcut`).
- Поддержать **несколько модификаторов** в комбо (сейчас один).
- **Escape** = отмена записи (откат к биндингу до сессии).
- Убрать ставшую ненужной логику: `clear-on-release`, `modifierIsSeeded`.
- Caption-предупреждение bare-key (B3) — **оставляем**: оно всё ещё корректно
  (голая печатная клавиша как хоткей реально перестаёт печатать символ),
  оттестировано, ортогонально рекордеру; удаление = лишний churn.
- Сохранить **keyCode**-триггер во всём пути (запись/хранение/матчинг/отображение
  не завязаны на символ раскладки).
- Тесты (TDD) на новую модель.

### Out (не трогаем)
- `HotkeyTapCombo` (маска модификаторов + keyCode) — структура данных та же.
- Мониторы (Carbon combo / `SpaceHoldMonitor` / `ModifierOnlyHotkeyMonitor`),
  роутинг (`isDropHoldTap`), конфликт-модель.
- Механизм голого правого модификатора (`R⌘`/`R⌥`) и агент (остаётся на `R⌘`,
  tap/hold) — не переопределяем; дефолты (hover `⌥1..⌥5`, useful links стрелки,
  agent close `⌥Q`) целы.
- `.holdSpace`-сентинел и Drop=hold-Space по умолчанию — остаются как есть
  (Space продолжает мапиться рекордером на `.holdSpace`).
- Расширение до 8 модификаторов / левые одиночными — отменено (не нужно).
- gesture tap/hold (B5) и `voiceTitle` (B6) — без изменений.

## Как работает рекордер (release-to-commit)

Состояние сессии записи:
- `pressedModifiers`: маска зажатых сейчас модификаторов (из `flagsChanged`).
- `pressedKey`: последняя зажатая не-модификаторная клавиша (keyCode), если есть.
- Поле показывает текущий набор: `[модификаторы-слева] + [символ]`.

События:
- **keyDown не-Escape не-модификатор** → `pressedKey` = этот keyCode (заменяет
  прежний — слот символа); обновить поле.
- **keyDown Escape** → отмена записи, откат, выход.
- **flagsChanged** → пересчитать `pressedModifiers` из флагов события; обновить поле.
- **Все клавиши отпущены** (физически отпущены модификаторы и клавиша) →
  **зафиксировать**: собрать `HotkeyShortcut` из набора:
  - есть символ → `.combo(модификаторы-маска + keyCode)` (голый символ = маска 0;
    Space → `.holdSpace`);
  - нет символа, один правый модификатор → `.modifier(R⌘/R⌥)`;
  - нет символа, несколько/левые модификаторы → невалидно, не фиксируем
    (ждём символ или сброс).
  Записать в draft (`assignShortcut`); поле показывает зафиксированное.
- Поле остаётся активным — новый набор перебивает; Escape выходит; Save применяет.

Нормализация: «до 3 одновременно» из Raycast ложится на «маска модификаторов +
1 символ». Два не-модификатора подряд — последний выигрывает (слот символа).

## Edge cases
- Завершённый combo `⌥D`: жмёшь ⌥ (поле `⌥`), D (поле `⌥D`), отпускаешь →
  фиксируется `⌥D`. **Модификатор больше не теряется** (отпускание = фиксация).
- Голый символ: жмёшь Space → отпустил → `.holdSpace`; жмёшь `←` → `.combo(←)`.
- Голый правый модификатор: жмёшь R⌥ → отпустил → `.modifier(.rightOption)`.
- Голый левый модификатор без символа → не фиксируем (невалидно).
- Несколько модификаторов без символа (`⌘⇧`) → не фиксируем, ждём символ.
- Escape во время набора → откат, биндинг прежний.
- Раскладка переключена после записи → хоткей срабатывает по той же физической
  клавише (keyCode), отображение — по символу текущей раскладки.

## Boundaries
- **Always:** keyCode-триггер; release-to-commit; Escape = отмена; Save применяет;
  агент на R⌘ цел; дефолты целы.
- **Never:** не трогать HotkeyTapCombo/мониторы/роутинг/конфликт-модель; не
  переопределять агента и hover-дефолты; не вводить левые одиночные модификаторы;
  не логировать нажатия.

## Open questions
- Лимит числа одновременных клавиш — жёсткий «3» или естественный (маска
  модификаторов + 1 символ без явного счётчика)? Дефолт: естественный, без
  жёсткого счётчика — Raycast ограничивает физикой клавиатуры.
- Синтез device-bit событий правых модификаторов в юнит-тестах невозможен через
  `NSEvent.keyEvent` (известный gap из B8) — голый правый модификатор тестируем
  через seeding/CGEvent; combo и голый символ синтезируются обычным путём.
