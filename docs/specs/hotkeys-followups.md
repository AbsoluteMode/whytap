## Что строим

### Пакет А — полировка hover-хоткеев
1. **⌥1 (Drop Mode) + нотификация.** Хоткей переключает Smart/Fast и показывает
   транзиентную пилюлю `ON Smart` / `ON Fast` в правом крыле острова (~1.5–2 c).
   Hover не раскрывается. Если сам триггер сломан (по репорту «не переключает») —
   диагностируем и чиним в этом же пункте.
2. **⌥2/⌥3/⌥4 (inline-панели) без промелька.** Программное раскрытие по хоткею
   не проигрывает hover-in анимацию — панель появляется сразу в раскрытом
   состоянии. Мышиный hover-путь не меняется.
3. **Хинты над тайлами — два кейкапа.** Вместо голого текста `⌥1` — два
   мини-кейкапа `[⌥][1]` side-by-side (выбран «вариант 3»), на базе
   существующего `KeycapView` (стиль Help-окна, уменьшенный), через
   `HotkeyHintView` (единственный entry point, `docs/hotkey.md`).
   ⌥-reveal не делаем.
   - **A5-корректировка (Максим, 13 июня):** хинт виден только над тайлом
     под курсором — у остальных тайлов скрыт. Одно правило без исключений:
     при программном ⌥N-раскрытии без мыши хинтов не видно (кто открыл
     хоткеем — хоткеи уже знает). Место под строку хинтов в лейауте
     резервируется всегда (скрытие через opacity — тайлы не прыгают);
     fade `easeInOut 0.15s`, синхронно с описанием тайла в нижней полосе
     (общий драйвер — `hoveredTool`).

### Пакет Б — тип активации голоса: Hold / Toggle
4. Для voice-хоткеев появляется выбор жеста **Hold / Toggle**:
   - **Toggle** = тап-старт → тап-стоп. Это реанимация старого ⌥/-флоу:
     `.tap`-ветка `dropHotkeyPressedRoute` жива и протестирована
     (`AppDelegateDropFlowRouteTests`), в UI она сейчас заблокирована.
   - **Drop voice:** переключатель жеста включается для combo-биндингов.
     **Space = hold-only** — при биндинге `.holdSpace` переключатель залочен
     на Hold с подсказкой почему (Space печатается; одиночный тап неотличим
     от обычного пробела при наборе).
   - **Agent voice:** переключатель уже есть; проверяем и доводим
     stop-семантику toggle (второй тап стопает), если она не доведена.
   - **Рекордер: модификатор больше не обязателен.** Сейчас рекордер требует
     «модификатор + клавиша», поэтому одиночную клавишу (Space, Tab, F-key)
     записать нельзя — со Space ушёл, назад не вернёшься. Валидация меняется
     на «1–2 клавиши»: одиночная голая клавиша — валидный биндинг.
     Голый Space мапится на `.holdSpace`.
   - **Чип-пресет «Hold Space» удаляется** из строки Drop voice — путь назад
     к дефолту теперь просто запись Space в рекордере.
   - **Голая клавиша + Hold** — через обобщённый CGEventTap-монитор коллеги
     (combo-swallow): удержание детектится и глотается, обычный тап
     проходит насквозь и печатает как обычно (как у hold-Space).
   - **Голая клавиша + Toggle** — через Carbon: клавиша глобально перестаёт
     печатать (Carbon забирает её себе). Это осознанный выбор юзера —
     в строке Settings показываем caption-предупреждение «клавиша перестанет
     печатать». Space — единственное исключение: hold-only (см. выше).
   - Toggle-combo (с модификатором) идёт через Carbon `RegisterEventHotKey` —
     нажатие проглатывается системой, своп символа (CGEventTap) не нужен.
     Hold-combo и hold-Space остаются на CGEventTap как есть.

## Почему
- ⌥1 сейчас выглядит «не работающим»: режим либо не переключается, либо
  переключается молча — пользователь не получает никакого фидбека.
- Программное раскрытие переиспользует мышиную hover-анимацию — выглядит как
  случайный промельк.
- Голые `⌥1..⌥5` читаются как случайный текст; кейкапы читаются как клавиши.
- Hold удобен не всем: части пользователей удобнее «тапнул в начале — тапнул
  в конце» (классика push-to-talk: hold-PTT vs toggle-PTT, как в Discord).
  Toggle у нас уже был (⌥/ до 10 июня) — даём его как опцию, не ломая Hold.

## Scope v1

### In
- Транзиентная mode-пилюля `ON Smart` / `ON Fast` в правом крыле + почин
  триггера ⌥1, если он сломан.
- Программное раскрытие hover без hover-in анимации.

- Переключатель Hold / Toggle у Drop voice (combo) и Agent voice;
  лейблы в UI: `Hold` / `Toggle` (внутренняя модель остаётся
  `HotkeyGesture.tap/.hold` — `Toggle` это display-имя tap для voice-строк).
- Залоченный Hold для `.holdSpace` с подсказкой.
- Рекордер без обязательного модификатора: валидация «1–2 клавиши»,
  одиночная голая клавиша — валидный биндинг; голый Space → `.holdSpace`.
  Caption-предупреждение для toggle на голой печатаемой клавише.

## Ключевые решения
| Решение | Обоснование |
|---|---|
| Mode-пилюля только для хоткей-пути | Клик мышью происходит при открытом hover — тайл сам показывает режим. |
| Пилюля подавляется priority-состояниями правого крыла (meeting recording, update pill) | Не воюем за слот; режим всё равно переключается. |
| Вариант 3 хинтов (два кейкапа) | Выбор Максима; `KeycapView` уже умеет рендер клавиш — нулевая новая сущность. |
| Toggle = реанимация `.tap`-роутинга, не новый жест | Код жив, протестирован, работал месяцами на ⌥/. |
| Space = hold-only, без исключений | Space печатается; toggle на нём = ложные старты при наборе. Юзер сам перебиндит на удобную клавишу (Tab, модификатор). |
| Рекордер без обязательного модификатора (1–2 клавиши) | «Юзер не идиот»: путь назад к Space — просто нажать его в рекордере; Tab/F-key как биндинг — его выбор. Меньше UI-сущностей (пресет-чип не нужен). |
| Голая клавиша: Hold — печать сохраняется (swallow), Toggle — клавиша стянута глобально + caption-предупреждение | Hold безопасен по построению; toggle — информированный выбор юзера. Space — единственный hard-block (hold-only). |
| Toggle-combo на Carbon без свопа | Carbon глотает зарегистрированный хоткей сам — так жил старый ⌥/. |

## Как работает
- **Mode-пилюля.** `AppState` публикует транзиентное событие смены режима
  (mode + токен монотонности). Правое крыло острова рендерит пилюлю по
  существующему паттерну транзиентных слотов и гасит её по таймеру.
  `onHoverSlotActivated` → `.toggleDropMode` дополнительно публикует событие.
- **Без промелька.** Путь `programmaticHoverExpansion` в `IslandView`
  раскрывает drawer без анимации (или с мгновенным переходом) — анимационный
  модификатор параметризуется источником раскрытия (mouse vs programmatic).
- **Хинты.** `hoverSlotHint(for:)` переходит со `style: .bare` на новый стиль
  «keycap-пара»; рендер ключей — `KeycapView` в tiny-размере, по одному
  кейкапу на глиф (`⌥` и `1`), без `+` (по `docs/hotkey.md`). Видимость
  хинта гейтится `hoveredTool == tool` (A5): opacity 0↔1 c fade 0.15s,
  лейаут-слот сохраняется.
- **Hold / Toggle.** `HotkeysSettingsView`: у Drop voice `allowsGestureSwitch`
  включается для combo, лочится для `.holdSpace`; лейблы voice-строк
  `Hold`/`Toggle`. Routing уже различает жесты (`dropHotkeyPressedRoute` /
  `dropHotkeyReleasedRoute`); `HotkeyShortcutMonitor` для tap-combo не
  подключает release-callback. Escape-cancel (`dropHotkeyCancelRoute`)
  работает для toggle как для hold.
- **Рекордер + Space.** Захват модификаторless Space в рекордере мапится на
  `.holdSpace` (+ gesture Hold). Конфликт-модель не меняется (физическая
  клавиша уже учитывается).

## User flows (happy path)
- **⌥1:** курсор где угодно → ⌥1 → в правом крыле на ~2 c появляется
  `ON Smart` → следующий Drop идёт через Smart.
- **⌥3:** History раскрывается сразу, без промелька hover-in.
- **Toggle-Drop:** Settings → Hotkeys → Drop voice → записал `⌥D` → жест
  `Toggle` → Save. Тап ⌥D — запись пошла, тап ⌥D — стоп и транскрипция.
  Escape во время записи — отмена.
- **Назад на Space:** Drop voice → рекордер → нажал Space → биндинг
  `Hold Space`, жест залочен на Hold.
- **Toggle на Tab:** Drop voice → рекордер → нажал Tab → жест `Toggle` →
  caption «Tab перестанет печатать» → Save. Тап Tab — старт, тап — стоп.

## Edge cases
- ⌥1 во время митинга / активного update-pill → режим переключается,
  пилюля не показывается (слот занят priority-состоянием).
- Быстрые повторные ⌥1 → пилюля обновляет текст и продлевает таймер,
  не плодит стопку.
- Toggle-Drop: тап во время `transcribing` (setup in flight) → pending stop
  (существующий `recordPendingStop`-путь).
- Запись голого Space в рекордере при «гонке» с активным hold-Space
  монитором → рекордер в приоритете (монитор Drop в это время остановлен —
  проверить, это уже текущее поведение записи).
- `.holdSpace` + попытка выставить Toggle программно (старые defaults) →
  нормализация в Hold при загрузке.
- Голая клавиша + Hold, юзер печатает этой клавишей быстро (тапы) →
  swallow-монитор пропускает тапы насквозь, печать не страдает (порог
  удержания как у hold-Space).
- Конфликт голой клавиши с той же клавишей в combo другого хоткея →
  существующая физическая модель конфликтов ловит (key-level).

## Boundaries
- **Always:** Hold остаётся дефолтом везде; Space hold-only; пилюля только
  для хоткей-пути; хинты через HotkeyHintView/KeycapView.
- **Never:** не трогать мышиный hover-путь и клик-пути тайлов; не вводить
  double-tap/эвристики на Space; не менять конфликт-модель; не логировать
  нажатия.
- **Ask:** финальная copy пилюли (`ON Smart` vs `Smart`) — дефолт `ON Smart`;
  точный размер/прозрачность кейкапов — на вкус при реализации.
